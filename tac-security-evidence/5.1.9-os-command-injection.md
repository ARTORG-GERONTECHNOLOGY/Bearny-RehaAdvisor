# Evidence — 5.1.9: Protection against OS command injection

## Summary

All `subprocess` calls in the backend use **list form** (no shell
interpolation). No user-supplied value is ever passed to a shell command.
`shell=True` is not used anywhere.

---

## subprocess — list form, no shell=True

File: `backend/core/tasks.py` — `renew_certificates` Celery task

```python
cmd = [
    "docker", "run", "--rm",
    "-v", f"{conf_path}:/etc/letsencrypt",
    "-v", f"{www_path}:/var/www/certbot",
    "certbot/certbot", "renew", "--non-interactive", "--quiet",
]
result = subprocess.run(cmd, capture_output=True, text=True, timeout=300)

reload = subprocess.run(
    ["docker", "exec", nginx_container, "nginx", "-s", "reload"],
    capture_output=True, text=True, timeout=30,
)
```

`conf_path`, `www_path`, and `nginx_container` are read from
`settings.CERTBOT_*` environment variables set at deploy time — not from
user requests.

---

## No user input reaches subprocess

```
$ grep -rn "subprocess\|os.system\|Popen" backend/ \
    | grep -v "test\|__pycache__" \
    | grep "request\.\|data\.\|body\."
(no output — no request data passed to shell commands)
```
