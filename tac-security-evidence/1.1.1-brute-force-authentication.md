# Evidence — 1.1.1: Authentication resistant to brute force attacks

## Summary

Authentication endpoints are protected by two independent brute-force controls:
1. **IP-level rate limiting** enforced by nginx at the gateway (before requests reach the application)
2. **Per-account lockout** enforced by the Django application layer

---

## Control 1 — nginx IP-rate limiting

File: `nginx/gateway.nginx.conf`

```nginx
# Rate-limit zones defined in the http context
limit_req_zone $binary_remote_addr zone=login_limit:10m    rate=5r/m;
limit_req_zone $binary_remote_addr zone=register_limit:10m rate=3r/m;

# Applied to the login endpoint
location /api/auth/login/ {
    limit_req zone=login_limit burst=5 nodelay;
    limit_req_status 429;
    ...
}
```

**Effect:** A single IP address may submit at most 5 login requests per minute.
Excess requests receive HTTP 429 immediately.

---

## Control 2 — Per-account lockout

File: `backend/utils/utils.py`

```python
def check_rate_limit(user):
    record = PasswordAttempt.objects(user=user).first()

    if not record:
        record = PasswordAttempt(user=user, count=0)
        record.save()
        return False, record

    now = datetime.utcnow()

    # Reset counter after 1 hour of inactivity
    if now - record.last_attempt > timedelta(hours=1):
        record.count = 0
        record.last_attempt = now
        record.save()
        return False, record

    # Lockout after 5 failed attempts within the 1-hour window
    if record.count >= 5:
        return True, record

    return False, record


def increment_attempt(record):
    record.count += 1
    record.last_attempt = datetime.utcnow()
    record.save()
```

**Effect:** After 5 failed login attempts within 1 hour the account is locked.
The counter resets automatically after 1 hour of inactivity.
