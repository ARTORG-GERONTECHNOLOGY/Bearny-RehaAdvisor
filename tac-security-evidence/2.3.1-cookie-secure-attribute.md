# Evidence — 2.3.1: Cookie-based session tokens have the 'Secure' attribute set

## Summary

Both auth cookies (`access_token`, `refresh_token`) are set with `Secure=True`
in all production deployments. The `secure` flag is derived from the `DEBUG`
setting — `False` in production — ensuring `Secure` is always present on the
public HTTPS endpoint.

---

## Code

File: `backend/core/views/auth_views.py` — `_set_auth_cookies`

```python
def _set_auth_cookies(response, access_token: str, refresh_token: str) -> None:
    secure = not getattr(_django_settings, "DEBUG", False)  # True in production

    response.set_cookie(
        "access_token",
        access_token,
        httponly=True,
        secure=secure,      # ← Secure attribute
        samesite="Strict",
        max_age=300,
    )
    response.set_cookie(
        "refresh_token",
        refresh_token,
        httponly=True,
        secure=secure,      # ← Secure attribute
        samesite="Strict",
        max_age=86400,
    )
```

File: `backend/api/settings/prod.py`

```python
DEBUG = False   # ensures secure=True for all cookies in production
```
