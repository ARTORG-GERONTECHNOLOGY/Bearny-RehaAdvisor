# Evidence — 1.3.1: Out-of-band verifier expires in a reasonable timeframe

## Summary

The email verification code (2FA out-of-band verifier) expires **5 minutes**
after issuance. Expired codes are rejected and deleted.

---

## Expiry set at issuance

File: `backend/core/views/auth_views.py` — `send_verification_code` function

```python
code = generate_code()
expires_at = timezone.now() + timedelta(minutes=5)

SMSVerification.objects(userId=user_id).delete()   # invalidate any previous code
SMSVerification(userId=user_id, code=code, expires_at=expires_at).save()
```

---

## Expiry enforced at verification

File: `backend/core/views/auth_views.py` — `verify_code_view` function

```python
expires_at = verification.expires_at
if timezone.is_naive(expires_at):
    expires_at_utc = expires_at.replace(tzinfo=dt_timezone.utc)
else:
    expires_at_utc = expires_at.astimezone(dt_timezone.utc)

now_utc = timezone.now().astimezone(dt_timezone.utc)

if expires_at_utc < now_utc:
    verification.delete()
    return JsonResponse({"error": "Verification code expired"}, status=400)
```

The comparison is always performed in UTC to avoid timezone-offset bypasses.
The expired record is deleted immediately upon detection.

---

## User-facing message in email

The verification email sent to the user explicitly states the expiry:

```html
<p>It will expire in <b>5 minutes</b>.</p>
```
