# Evidence — 6.6.1: Browser storage securely cleared on logout

## Summary

The `authStore.logout()` method clears both `localStorage` and
`sessionStorage` completely before the page transitions to the logged-out
state. Auth cookies are cleared server-side by the logout API.

---

## clearStorage() — both storage areas cleared

File: `frontend/src/stores/authStore.ts`

```typescript
clearStorage() {
  // Preserve non-sensitive preferences only
  const lang = localStorage.getItem('i18nextLng');
  const notificationsEnabled = localStorage.getItem('notifications-enabled');
  const surveyIndex = localStorage.getItem('survey_index');
  const surveySessionId = localStorage.getItem('survey_sessionId');

  sessionStorage.clear();   // ← all sessionStorage cleared
  localStorage.clear();     // ← all localStorage cleared

  // Restore non-sensitive preferences
  if (lang) localStorage.setItem('i18nextLng', lang);
  if (notificationsEnabled) localStorage.setItem('notifications-enabled', notificationsEnabled);
  if (surveyIndex !== null) localStorage.setItem('survey_index', surveyIndex);
  if (surveySessionId) localStorage.setItem('survey_sessionId', surveySessionId);
}
```

Only language preference and notification settings are re-saved — no auth
state, user IDs, or tokens are preserved.

---

## logout() — calls clearStorage after API call

```typescript
logout = async () => {
  const userId = this.id;
  try {
    await apiClient.post('/auth/logout/', { userId });
  } catch {
    // do not keep stale error visible; logout should proceed
  }
  this.clearStorage();   // ← always runs, even if API call fails
  ...
}
```

Storage is cleared even if the server-side logout API call fails.

---

## Server-side — auth cookies deleted

File: `backend/core/views/auth_views.py`

```python
_resp = JsonResponse({"message": "Logout successful"}, status=200)
_clear_auth_cookies(_resp)   # deletes access_token + refresh_token cookies
return _resp
```
