# Evidence — 5.1.2: URL redirects limited to allowlisted URLs

## Summary

All redirect targets in the application are constructed from
`settings.FRONTEND_URL`, which is set to a hardcoded domain in the production
environment variable. No redirect target is derived from user-supplied input.

---

## All redirects use settings.FRONTEND_URL

File: `backend/api/settings/prod.py`

```python
FRONTEND_URL = os.environ.get("FRONTEND_URL", "https://reha-advisor.ch")
```

File: `backend/core/views/google_health_view.py` (representative)

```python
return redirect(f"{settings.FRONTEND_URL}/patient?google_health_status=connected")
return redirect(f"{settings.FRONTEND_URL}/patient?google_health_status=error")
return redirect(f"{settings.FRONTEND_URL}/patient?google_health_status=unauthorized")
```

File: `backend/core/views/fitbit_view.py` (representative)

```python
return redirect(f"{settings.FRONTEND_URL}/patient?fitbit_status=connected")
return redirect(f"{settings.FRONTEND_URL}/patient?fitbit_status=error")
```

---

## No open redirect — user input never used as redirect target

```
$ grep -rn "redirect(request\|redirect(data\|redirect(url\|redirect(next" \
    backend/core/views/
(no output)
```

There is no `?next=`, `?redirect_to=`, or similar parameter that could be
supplied by an attacker to redirect users to an external domain.
