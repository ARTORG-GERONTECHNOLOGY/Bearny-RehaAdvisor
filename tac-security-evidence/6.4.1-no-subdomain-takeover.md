# Evidence — 6.4.1: Not susceptible to subdomain takeover

## Summary

All subdomains used by the application point to server infrastructure that
is fully under the team's control. No CNAME or NS records point to external
services that could be abandoned and claimed by an attacker.

---

## DNS configuration

The application uses two hostnames:
- `reha-advisor.ch` — production
- `dev.reha-advisor.ch` — development

Both A records point directly to the VPS IP address. There are no
dangling CNAME records pointing to third-party services (Heroku, GitHub
Pages, AWS CloudFront, Netlify, etc.).

---

## All proxy_pass targets are internal Docker services

File: `nginx/gateway.nginx.conf`

```nginx
proxy_pass http://nginx-prod:80;    # internal Docker network
proxy_pass http://nginx:80;         # internal Docker network (dev)
```

There are no `proxy_pass` directives pointing to external cloud services
that could be de-provisioned.

---

## Verification

```
$ dig reha-advisor.ch A +short
<server-IP>

$ dig dev.reha-advisor.ch A +short
<server-IP>

$ dig CNAME reha-advisor.ch
(no CNAME record — direct A record)
```

No external service dependency exists at the DNS level that could create
a subdomain takeover opportunity.
