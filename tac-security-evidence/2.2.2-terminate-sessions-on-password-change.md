# Evidence — 2.2.2: All active sessions terminated after password change or reset

## Summary

Both the self-service password change and the therapist-initiated patient password
reset call `invalidate_user_tokens(user_id)` immediately after saving the new
password. This stores a "valid-after" epoch in Redis; any JWT with an `iat`
(issued-at) earlier than that epoch is rejected, effectively invalidating every
outstanding session for the user in a single write.

---

## Password change — `change_password` view

File: `backend/core/views/user_views.py`

```python
# Save new password
user.pwdhash = make_password(new_password)
user.save()

# Invalidate all outstanding tokens so existing sessions cannot continue
# after a password change.
invalidate_user_tokens(str(user.id))

Logs.objects.create(
    userId=user,
    action="UPDATE_PROFILE",
    actor_role="Therapist",
    details="Password changed securely",
)
return JsonResponse({"message": "Password changed successfully"}, status=200)
```

## Mechanism — Redis valid-from timestamp

File: `backend/core/token_revocation.py`

```python
_VALID_FROM_PREFIX = "user_valid_from:"

def invalidate_user_tokens(user_id: str, ttl_seconds: int = 86400) -> None:
    """
    Set a 'valid-after' epoch for a user.

    Any JWT whose `iat` (issued-at) is earlier than this timestamp will be
    rejected. Call this after a password change or reset to invalidate all
    outstanding sessions.

    ttl_seconds defaults to the refresh token lifetime (1 day).
    """
    import time
    rc = _get_redis()
    rc.set(f"{_VALID_FROM_PREFIX}{user_id}", str(int(time.time())), ex=ttl_seconds)

def get_user_valid_from(user_id: str) -> int:
    """Return the 'valid-after' epoch for a user, or 0 if not set."""
    rc = _get_redis()
    val = rc.get(f"{_VALID_FROM_PREFIX}{user_id}")
    return int(val) if val else 0
```

`JWTAuthMiddleware` calls `get_user_valid_from` on every authenticated request
and compares it against the token's `iat` claim. Tokens issued before the
password-change moment are rejected with HTTP 401.
