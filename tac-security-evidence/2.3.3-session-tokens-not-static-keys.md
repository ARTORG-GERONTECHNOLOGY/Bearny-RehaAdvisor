# Evidence — 2.3.3: Application uses session tokens rather than static API keys

## Summary

Authentication is based exclusively on short-lived JWTs (5 min access,
1 day refresh). No static API keys, shared secrets, or long-lived bearer
tokens are used for user session management.

---

## Token lifetimes

File: `backend/api/settings/base.py`

```python
SIMPLE_JWT = {
    "ACCESS_TOKEN_LIFETIME":  timedelta(minutes=5),
    "REFRESH_TOKEN_LIFETIME": timedelta(days=1),
    "ROTATE_REFRESH_TOKENS":  True,
    "BLACKLIST_AFTER_ROTATION": True,
    "ALGORITHM": "HS256",
}
```

- Each refresh rotates the token (old one is blacklisted)
- Access tokens expire in 5 minutes
- No token is permanent or static

---

## No static API keys for user sessions

```
$ grep -rn "api_key\|API_KEY\|static.*token\|permanent.*token" \
    backend/core/views/auth_views.py
(no output — no static API key auth found)
```

The only long-lived credential in the system is `DJANGO_SECRET_KEY`
(used to sign tokens server-side) which is never exposed to clients.
