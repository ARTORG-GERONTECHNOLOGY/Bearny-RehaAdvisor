# Evidence — 2.4.1: Re-authentication required before sensitive transactions

## Summary

The password change endpoint requires the user to supply their **current
password** before a new password is accepted. This is enforced at the API
layer regardless of whether the caller has a valid JWT.

---

## Password change — requires old password

File: `backend/core/views/user_views.py` — `change_password`

```python
old_password = data.get("old_password")
new_password = data.get("new_password")

if not old_password or not new_password:
    return JsonResponse({"error": "Missing password fields"}, status=400)

# Verify current password before allowing the change
if not check_password(old_password, user.pwdhash):
    attempt.count += 1
    attempt.last_attempt = now
    attempt.save()
    return JsonResponse({"error": "Old password incorrect"}, status=403)

# ... strength check ...
user.pwdhash = make_password(new_password)
user.save()
invalidate_user_tokens(str(user.id))   # all sessions terminated after change
```

A stolen access token alone is **not sufficient** to change a password —
the attacker would also need to know the current password.

## Other sensitive operations

| Operation | Auth mechanism |
|---|---|
| Login | Password + 2FA (therapist/admin) |
| Password change | Valid JWT + current password |
| Password reset | Admin/therapist-initiated only; user cannot self-reset without email access |
| Data export | Valid JWT with Therapist role |
| Patient data access | Valid JWT + clinic ownership check |
