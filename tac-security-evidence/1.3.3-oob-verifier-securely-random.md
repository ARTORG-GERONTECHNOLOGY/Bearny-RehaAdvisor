# Evidence — 1.3.3: Out-of-band verifier is securely random

## Summary

The 6-digit verification code is generated using Python's `secrets` module,
which is backed by the operating system's cryptographically secure random
number generator (`os.urandom` / `getrandom(2)`).

---

## Code generation

File: `backend/core/views/auth_views.py` (line 998)

```python
import secrets
import string

def generate_code(length=6):
    return "".join(secrets.choice(string.digits) for _ in range(length))
```

### Why `secrets.choice` and not `random.choice`

| Module | RNG source | Suitable for security? |
|--------|-----------|------------------------|
| `random` | Mersenne Twister (deterministic, seedable) | No |
| `secrets` | OS CSPRNG (`os.urandom`) | Yes |

The `secrets` module is explicitly recommended by PEP 506 and the Python
documentation for generating tokens, OTPs, and any value where unpredictability
is a security requirement.

The earlier implementation used `random.choices` and was replaced with
`secrets.choice` as a CASA AL1 remediation item.

---

## Entropy

- Alphabet: digits 0–9 (10 symbols)
- Length: 6
- Entropy: log₂(10⁶) ≈ **19.9 bits**

This meets ASVS 1.3.3 (minimum 20-bit entropy for OOB verifiers is typically
required at Level 2; Level 1 requires only that the value is "securely random").
The brute-force protection (10 attempts / 30 min — see 1.3.4) further mitigates
the limited numeric range.
