# Evidence — 6.2.1: Debug mode disabled in production

## Summary

`DEBUG = False` is set unconditionally in the production settings file.
Django's debug mode (which exposes stack traces, SQL queries, and settings
values to browser responses) is never enabled in production.

---

## Production settings

File: `backend/api/settings/prod.py`

```python
DEBUG = False
```

This is a hardcoded value — not derived from an environment variable —
so it cannot be accidentally enabled via a misconfigured `.env.prod`.

---

## Effect of DEBUG=False

- Django error pages return generic 500 responses (no stack trace)
- SQL query log is not exposed in responses
- `ALLOWED_HOSTS` is enforced (requests to unknown hosts return 400)
- Static files are not served by Django itself (handled by nginx)

---

## Verification on production container

```
$ docker exec django-prod /opt/conda/envs/teleRehabApp/bin/python -c "
import django, os
os.environ['DJANGO_SETTINGS_MODULE'] = 'api.settings.prod'
django.setup()
from django.conf import settings
print('DEBUG:', settings.DEBUG)
"

DEBUG: False
```
