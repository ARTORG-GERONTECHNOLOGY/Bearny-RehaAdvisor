# Evidence — 5.2.1: Malicious file uploads prevented

## Summary

File uploads are validated against a strict extension allowlist. MIME type
is derived server-side from the extension mapping — not trusted from the
`Content-Type` header. Uploaded files are stored in object storage and never
executed by the server.

---

## Extension allowlist

File: `backend/core/views/intervention_media_upload.py`

```python
# Only these extensions are accepted
_EXT_INFO = {
    "mp4":  ("video",  "video/mp4",          "videos"),
    "mp3":  ("audio",  "audio/mpeg",          "audio"),
    "m4a":  ("audio",  "audio/mp4",           "audio"),
    "wav":  ("audio",  "audio/wav",           "audio"),
    "pdf":  ("pdf",    "application/pdf",     "documents"),
    "jpg":  ("image",  "image/jpeg",          "images"),
    "jpeg": ("image",  "image/jpeg",          "images"),
    "png":  ("image",  "image/png",           "images"),
}
```

Any file with an extension not in this dict is rejected before storage.

---

## Validation flow

```python
filename = (getattr(file_obj, "name", "") or "").strip()
m = _FILENAME_RE.match(filename)      # strict regex on filename structure
if not m:
    return error("Invalid filename format")

ext = filename.rsplit(".", 1)[-1].lower()
if ext not in _EXT_INFO:
    return error(f"Invalid extension. Valid: mp4, mp3, m4a, wav, pdf, jpg, jpeg, png.")
```

---

## Files never executed

Uploaded files are stored as binary blobs in MongoDB GridFS or a
configured object store. They are served back as static content with the
correct `Content-Type` header. The server never executes, includes, or
interprets uploaded files.

---

## Excel import (intervention library)

File: `backend/core/views/intervention_import.py`

```python
filename = (getattr(up, "name", "") or "").lower()
has_xlsx_ext = filename.endswith(".xlsx") or filename.endswith(".xlsm")
if not has_xlsx_ext:
    return error("Only .xlsx/.xlsm files are accepted")
```

Excel files are parsed by `openpyxl` in read-only mode; macros are not
executed.
