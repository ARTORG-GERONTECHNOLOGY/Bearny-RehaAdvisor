# Evidence — 3.2.2: OAuth validates redirect_uri and state parameter (CSRF protection)

## Summary

Both OAuth integrations generate a **cryptographically random nonce** at flow
initiation, store it in Redis, and validate it in the callback. The
`redirect_uri` is a hardcoded server-side constant — never derived from user
input.

---

## Fitbit — nonce generation

File: `backend/core/views/fitbit_view.py`

```python
def fitbit_auth_init(request):
    """Generate a one-time CSRF nonce for the Fitbit OAuth state parameter."""
    nonce = secrets.token_urlsafe(32)   # 256 bits of entropy
    rc = _get_redis()
    rc.set(f"fitbit_nonce:{nonce}", patient_id, ex=_FITBIT_NONCE_TTL)
    return JsonResponse({"nonce": nonce})
```

State format passed to Fitbit: `state=<nonce>:<patientId>`

---

## Fitbit — nonce validation in callback

```python
state = request.GET.get("state", "")
nonce, patient_id_str = state.split(":", 1)

stored = rc.get(f"fitbit_nonce:{nonce}")
if not stored:
    logger.warning("[fitbit_callback] nonce not found or expired: %s", nonce)
    return redirect(...fitbit_status=error...)
rc.delete(f"fitbit_nonce:{nonce}")   # one-time use
```

## Google Health — nonce generation and validation

File: `backend/core/views/google_health_view.py`

```python
# Initiation
nonce = secrets.token_urlsafe(32)
rc.set(f"oauth_nonce:{nonce}", patient_id, ex=_OAUTH_NONCE_TTL)

# Callback
nonce, patient_id_from_state = state.split(":", 1)
stored = rc.get(f"oauth_nonce:{nonce}")
if not stored:
    logger.warning("[google_health_callback] nonce not found or expired")
    return redirect(...google_health_status=unauthorized...)
if stored.decode() != patient_id_from_state:
    logger.warning("[google_health_callback] nonce/patientId mismatch")
    return redirect(...google_health_status=unauthorized...)
rc.delete(f"oauth_nonce:{nonce}")   # one-time use
```

---

## redirect_uri — hardcoded server-side

```python
# fitbit_view.py
"redirect_uri": settings.FITBIT_REDIRECT_URI,   # from env var, set at deploy time

# google_health_view.py
"redirect_uri": settings.GOOGLE_HEALTH_REDIRECT_URI,
```

`FITBIT_REDIRECT_URI` and `GOOGLE_HEALTH_REDIRECT_URI` are set in `.env.prod`
to the exact callback URLs registered in each OAuth provider's console.
No user-supplied redirect_uri is accepted.
