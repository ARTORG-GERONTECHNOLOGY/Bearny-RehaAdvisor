# Evidence — 4.1.1: TLS 1.2+ enforced with secure cipher suites

## Summary

The gateway nginx terminates all TLS connections. TLS 1.0 and 1.1 are
explicitly disabled. Only TLS 1.2 and 1.3 are accepted. A modern, forward-
secret cipher suite list is configured. HTTP is redirected to HTTPS.

---

## nginx configuration

File: `nginx/gateway.nginx.conf` (production server block)

```nginx
ssl_protocols TLSv1.2 TLSv1.3;

ssl_ciphers ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:\
            ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384:\
            ECDHE-ECDSA-CHACHA20-POLY1305:ECDHE-RSA-CHACHA20-POLY1305;

ssl_session_cache shared:SSL:10m;
ssl_session_timeout 1d;
```

All ciphers use ECDHE key exchange (forward secrecy). No RC4, 3DES, NULL,
EXPORT, or CBC-mode ciphers are listed.

---

## HTTP → HTTPS redirect

```nginx
server {
    listen 80;
    server_name reha-advisor.ch www.reha-advisor.ch;
    return 301 https://$host$request_uri;
}
```

All plain-HTTP requests are redirected to HTTPS with a permanent redirect.

---

## HSTS header

File: `nginx/conf/prod.reha-advisor.nginx.conf`

```nginx
add_header Strict-Transport-Security "max-age=31536000; includeSubDomains; preload" always;
```

HSTS with 1-year max-age and preload ensures browsers never attempt
plain-HTTP connections after the first visit.
