# Evidence — 5.1.5: Server-Side Request Forgery (SSRF) prevention

## Summary

All outbound HTTP requests from the backend target hardcoded URLs from server
environment variables. No outbound URL is constructed from user-supplied input.

---

## All external URLs are hardcoded or from server env vars

| Destination | URL source |
|---|---|
| Fitbit token endpoint | `https://api.fitbit.com/oauth2/token` (hardcoded) |
| Fitbit API | `https://api.fitbit.com/1/user/...` (hardcoded) |
| Google OAuth token | `https://oauth2.googleapis.com/token` (hardcoded) |
| Google Health API | `https://healthcare.googleapis.com/...` (hardcoded) |
| REDCap API | `settings.REDCAP_API_URL` (server env var) |
| Email SMTP | `settings.EMAIL_HOST` (server env var) |

---

## Fitbit — hardcoded URL

File: `backend/core/views/fitbit_view.py`

```python
token_url = "https://api.fitbit.com/oauth2/token"
response = requests.post(token_url, auth=basic_auth, data=data, headers=headers)
```

---

## Google Health — hardcoded URL

File: `backend/core/views/google_health_view.py`

```python
token_response = requests.post(
    "https://oauth2.googleapis.com/token",   # hardcoded
    data={...}
)
```

## No user-supplied URL in outbound requests

```
$ grep -rn "requests.get\|requests.post\|requests.put" backend/core/views/ \
    | grep -v "test\|#" \
    | grep "request\.\|data\.\|body\."
(no output — no outbound URLs derived from request data)
```
