# Evidence — 5.1.4: Template injection protection

## Summary

The frontend is a React SPA — there is no server-side HTML template rendering
of user input. Backend email templates use Python f-strings for non-sensitive
fields (names, codes) and never render arbitrary user input into executable
template expressions.

---

## Frontend — React JSX, no server-side rendering

React JSX escapes all interpolated values. User input is never interpolated
into raw HTML strings. There is no use of a server-side template engine
(Jinja2, Django templates) with user-controlled variables in the frontend.

---

## Backend — no server-side HTML templates with user input

Django's template engine is not used to render user-supplied content.
The only Django templates in the project are the admin panel (served only
to loopback) and email templates.

Email templates use Python f-strings — user-controlled data is limited to
string interpolation (username, verification code) and is never interpreted
as a template expression:

```python
html_content = f"""
<p>Dear {user.username},</p>
<p>Your verification code is: <b>{code}</b></p>
<p>It will expire in <b>5 minutes</b>.</p>
"""
```

`user.username` and `code` are plain strings — no template engine evaluates
them as expressions.

---
