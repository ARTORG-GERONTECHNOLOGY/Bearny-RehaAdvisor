# Evidence — 6.3.1: Origin header not used for authentication or access control

## Summary

Authentication is based entirely on JWT tokens validated by `JWTAuthMiddleware`.
The `Origin` header is never inspected for authentication or access control
decisions. CORS is configured as an explicit allow-list, not used as a security
boundary.

---

## No origin-based auth decisions

```
$ grep -rn "request.headers.*Origin\|HTTP_ORIGIN\|origin.*auth\|auth.*origin" \
    backend/core/ | grep -v "test\|__pycache__\|cors\|#"
(no output)
```

---

## CORS configuration — allow-list only

File: `backend/api/settings/base.py` (CORS_ALLOWED_ORIGINS)

CORS headers are set by `django-cors-headers` to allow the React SPA origin.
This is a browser-level convenience, not a security control — the CORS
allow-list does not restrict which requests are authenticated.

Every request still requires a valid JWT regardless of origin.

---

## Auth middleware — no origin check

File: `backend/core/middleware.py` — `JWTAuthMiddleware`

```python
def __call__(self, request):
    # ...
    token_str = request.COOKIES.get("access_token", "")
    if not token_str:
        auth_header = request.headers.get("Authorization", "")
        if auth_header.startswith("Bearer "):
            token_str = auth_header.split(" ", 1)[1]
    # No Origin check — only token validation matters
    token = AccessToken(token_str)
    ...
```
