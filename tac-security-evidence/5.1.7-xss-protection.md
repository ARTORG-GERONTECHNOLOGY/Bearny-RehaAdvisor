# Evidence — 5.1.7: XSS protection — reflected, stored, and DOM-based

## Summary

The React SPA escapes all dynamic content by default. A Content-Security-Policy
header restricts script execution to same-origin only. The single
`dangerouslySetInnerHTML` usage is limited to chart color CSS values from
static configuration — not user input.

---

## React JSX — automatic HTML escaping

All `{variable}` interpolations in JSX are HTML-escaped before DOM insertion.
User-supplied strings (patient names, therapist notes) are rendered through
JSX exclusively and cannot inject executable HTML.

---

## Content-Security-Policy header

File: `nginx/conf/prod.reha-advisor.nginx.conf`

```nginx
add_header Content-Security-Policy
  "default-src 'self';
   script-src 'self' 'unsafe-inline' 'unsafe-eval';
   style-src 'self' 'unsafe-inline';
   img-src 'self' data: blob: https:;
   font-src 'self' data:;
   connect-src 'self' https://*.sentry.io https://*.ingest.sentry.io;
   media-src 'self' blob: https:;
   object-src 'none';
   frame-src https:;
   frame-ancestors 'none';" always;
```

`frame-ancestors 'none'` prevents clickjacking.
`object-src 'none'` blocks Flash/plugin-based XSS.

---

## dangerouslySetInnerHTML — not user input

File: `frontend/src/components/ui/chart.tsx`

```tsx
// Only CSS custom property declarations from hardcoded chart color config:
dangerouslySetInnerHTML={{
  __html: `[data-chart=${id}] { --color-${key}: ${color}; }`
  // color = hex value from static chart configuration, not user input
}}
```

---

## X-Content-Type-Options header

```nginx
add_header X-Content-Type-Options "nosniff" always;
```

Prevents MIME-sniffing attacks that could reinterpret a response as
executable script.
