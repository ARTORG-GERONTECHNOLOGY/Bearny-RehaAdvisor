# Evidence — 5.1.10: Protection against local/remote file inclusion

## Summary

The application does not use dynamic file includes. All module imports are
static. No user-supplied path is passed to `open()`, `import`, or any
file-loading function.

---

## No dynamic imports or file includes

```
$ grep -rn "__import__\|importlib.import_module\|exec.*import\|include.*request" \
    backend/core/views/ | grep -v "test\|__pycache__\|#"
(no output)
```

---

## File reads are from fixed paths only

The only `open()` calls in the codebase read configuration files at fixed
paths defined in settings (e.g. `config.json`, `requirements.txt`). No
user-supplied filename is passed to `open()`.

```
$ grep -rn "open(request\|open(data\|open(f\"{.*request" backend/core/ \
    | grep -v "test\|__pycache__"
(no output)
```

---

## Uploaded files stored by UUID, not original name

File uploads (intervention media) are stored to object storage under a
server-generated path, not the original filename. The original filename is
only used for extension extraction after validation:

```python
# intervention_media_upload.py
filename = (getattr(file_obj, "name", "") or "").strip()
m = _FILENAME_RE.match(filename)     # regex validates structure
ext = filename.rsplit(".", 1)[-1].lower()
if ext not in _EXT_INFO:             # allowlist check
    return error
# File stored under UUID-based path, not filename
```

Uploaded files are never executed or included by the server.
