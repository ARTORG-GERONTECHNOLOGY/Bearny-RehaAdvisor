# Evidence — 1.3.4: Out-of-band verifier resistant to brute force attacks

## Summary

Verification code guessing is limited to **10 attempts per 30-minute window**
per user. After the limit is reached the user receives HTTP 429 and must
request a new code.

---

## Rate limiting constants

File: `backend/utils/utils.py`

```python
_VERIFY_MAX_ATTEMPTS = 10
_VERIFY_WINDOW_MINUTES = 30
```

---

## Attempt tracking

File: `backend/utils/utils.py` — `check_verify_rate_limit` function

```python
def check_verify_rate_limit(key: str):
    """
    Returns (is_locked, record) for the given key.
    Resets after _VERIFY_WINDOW_MINUTES (30) minutes.
    """
    record = VerifyAttempt.objects(key=key).first()
    now = datetime.utcnow()

    if not record:
        record = VerifyAttempt(key=key, count=0, last_attempt=now)
        record.save()
        return False, record

    if now - record.last_attempt > timedelta(minutes=_VERIFY_WINDOW_MINUTES):
        record.count = 0
        record.last_attempt = now
        record.save()
        return False, record

    if record.count >= _VERIFY_MAX_ATTEMPTS:
        return True, record

    return False, record
```

## Enforcement in verify_code_view

File: `backend/core/views/auth_views.py` — `verify_code_view` function

```python
is_locked, verify_record = check_verify_rate_limit(user_id)
if is_locked:
    return JsonResponse(
        {"error": "Too many verification attempts. Please request a new code."},
        status=429,
    )

verification = SMSVerification.objects(userId=user_id, code=code)...
if not verification:
    increment_verify_attempt(verify_record)   # count each failed guess
    return JsonResponse({"error": "Invalid verification code"}, status=400)
```

Failed guesses increment the counter; successful verification resets it.
The 30-minute window resets automatically — no admin intervention needed.
