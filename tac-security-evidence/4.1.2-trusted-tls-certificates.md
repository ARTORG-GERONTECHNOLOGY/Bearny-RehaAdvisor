# Evidence — 4.1.2: Trusted TLS certificates

## Summary

Production TLS certificates are issued by **Let's Encrypt** (a publicly
trusted CA). Certificates are auto-renewed by a Celery beat task before
expiry. No self-signed certificates are used on the public endpoint.

---

## Certificate configuration

File: `nginx/gateway.nginx.conf`

```nginx
ssl_certificate     /etc/letsencrypt/live/reha-advisor.ch/fullchain.pem;
ssl_certificate_key /etc/letsencrypt/live/reha-advisor.ch/privkey.pem;
```

`fullchain.pem` includes the intermediate CA certificate, so all clients
can build a complete trust chain to the Let's Encrypt root CA.

---

## Auto-renewal via Celery

File: `backend/core/tasks.py` — `renew_certificates` task

```python
cmd = [
    "docker", "run", "--rm",
    "-v", f"{conf_path}:/etc/letsencrypt",
    "-v", f"{www_path}:/var/www/certbot",
    "certbot/certbot", "renew", "--non-interactive", "--quiet",
]
subprocess.run(cmd, capture_output=True, text=True, timeout=300)
```

Certbot runs non-interactively on a schedule and renews the certificate
before it expires (Let's Encrypt issues 90-day certs; renewal is attempted
at 60 days).
