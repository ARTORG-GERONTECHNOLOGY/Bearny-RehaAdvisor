# Evidence — 3.2.3 / 3.3.x: Administrative interfaces use MFA and are IP-restricted

## Summary

The Django admin panel (`/api/admin/`) is protected by two independent
controls: IP allowlisting at the nginx gateway (loopback only, reachable
only via SSH tunnel) and the application-level 2FA requirement for all
Admin-role users.

---

## nginx — admin restricted to localhost

File: `nginx/gateway.nginx.conf`

```nginx
location /api/admin/ {
    # Intentionally restricted to loopback only: admins reach this endpoint
    # by SSH-tunnelling to the server
    # (ssh -L 8443:localhost:443 user@reha-advisor.ch)
    allow 127.0.0.1;
    allow ::1;
    deny all;    # everyone else is rejected before reaching Django

    proxy_pass http://nginx-prod:80;
    ...
}
```

Attempting to access `https://reha-advisor.ch/api/admin/` from the public
internet returns HTTP 403 before the request reaches Django.

---

## Application-level 2FA for Admin accounts

File: `backend/core/views/auth_views.py`

```python
if user.role in ("Therapist", "Admin"):
    # 2FA required — send email verification code before issuing JWT
    ...
    return JsonResponse({"require_2fa": True, ...}, status=200)
```

Admin users must complete the email-based 2FA flow before a JWT is issued,
in addition to password authentication.
