# Evidence — 3.1.4: IDOR protection on sensitive resources

## Summary

Every patient data endpoint enforces an ownership check before returning data:
the caller must be the patient themselves **or** a therapist whose assigned
clinics include the patient's clinic. Passing an arbitrary patient ObjectId
returns HTTP 403 if the caller has no clinical relationship with that patient.

---

## IDOR guard pattern (applied at multiple endpoints)

File: `backend/core/views/patient_views.py`

```python
# IDOR guard: allow the patient themselves or a therapist in the same clinic.
if not getattr(settings, "TESTING", False) and getattr(request.user, "id", None) is not None:
    caller_id = str(request.user.id)
    if caller_id != patient_id:
        caller_therapist = get_therapist_for_user(request.user)
        patient_clinic = getattr(patient, "clinic", None)
        if not caller_therapist or patient_clinic not in (caller_therapist.clinics or []):
            return JsonResponse(
                {"error": "You are not authorised to access this patient's data."},
                status=403
            )
```

This pattern is applied in:
- `get_profile` (patient profile)
- `get_patient_plan_for_therapist` (rehabilitation plan)
- `mark_intervention_completed` / `mark_intervention_uncompleted`
- `get_fitbit_health_data` (Fitbit summary)
