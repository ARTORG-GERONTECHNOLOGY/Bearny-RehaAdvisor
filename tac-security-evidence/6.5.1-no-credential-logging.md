# Evidence — 6.5.1: No credentials or session tokens logged

## Summary

Passwords are never logged. JWT tokens are not logged. OAuth tokens are not
logged in success paths. The Fitbit error path logs the HTTP response body
only on token exchange failure (which contains an error message, not a
valid token), and only at ERROR level (not written to persistent logs in
normal operation).

## JWT tokens — not logged

The `ApiAuditMiddleware` logs `method path status user_id ip` per request —
no token values:

File: `backend/core/middleware.py`

```python
logger.info(
    "%s %s %s user_id=%s ip=%s",
    request.method, path, response.status_code, user_id, ip,

```

## OAuth token exchange — success path logs only user ID

File: `backend/core/views/fitbit_view.py`

```python
# Success path — only user ID is logged, no token value:
logger.info(f"[fitbit_callback] Fitbit token saved for user {user.id}")

# Error path — logs HTTP error response from Fitbit (no valid token present):
logger.error(
    "[fitbit_callback] Fitbit token exchange failed (status %s): %s",
    response.status_code,
    response.text,    # Fitbit error body, e.g. {"errors":[{"errorType":"invalid_grant"}]}
)
```

The error path logs `response.text` only when Fitbit returns a non-200
status code — at that point no valid token was issued, so no token value
is exposed.

---

## OAuth tokens stored encrypted in MongoDB

OAuth `access_token` and `refresh_token` values are encrypted at rest using
Fernet (AES-128-CBC + HMAC-SHA256) before being written to MongoDB.
Even if logs were to capture a database dump, the token values would be
encrypted ciphertext.
