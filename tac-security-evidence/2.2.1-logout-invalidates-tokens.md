# Evidence — 2.2.1: Logout invalidates all session tokens including refresh tokens

## Summary

On logout, both the **access token** and the **refresh token** are individually
revoked in Redis via a JTI denylist. The auth cookies are then cleared.
Any subsequent request using either revoked token is rejected by the
`JWTAuthMiddleware` before reaching any view.

---

## logout_view — token revocation

File: `backend/core/views/auth_views.py`

```python
def logout_view(request):
    """
    Logs a user out and creates a log entry.
    Endpoint: POST /api/auth/logout/
    """
    try:
        data = json.loads(request.body)
        user_id = data.get("userId")
        user = User.objects.get(pk=ObjectId(user_id))

        # Revoke the refresh token so it cannot obtain new access tokens.
        from rest_framework_simplejwt.tokens import RefreshToken as _RefreshToken
        refresh_str = request.COOKIES.get("refresh_token", "")
        if refresh_str:
            try:
                refresh = _RefreshToken(refresh_str)
                jti = refresh.payload.get("jti", "")
                if jti:
                    revoke_jti(jti, ttl_seconds=86400)  # max refresh token lifetime
            except Exception:
                logger.warning("[logout_view] Could not revoke refresh token JTI")

        # Also revoke the access token so it cannot be replayed within its 5-min window.
        access_str = request.COOKIES.get("access_token", "")
        if access_str:
            try:
                from rest_framework_simplejwt.tokens import AccessToken as _AccessToken
                access = _AccessToken(access_str)
                jti = access.payload.get("jti", "")
                if jti:
                    revoke_jti(jti, ttl_seconds=300)  # max access token lifetime
            except Exception:
                logger.warning("[logout_view] Could not revoke access token JTI")

        Logs.objects.create(userId=user, action="LOGOUT", actor_role=user.role)
        _resp = JsonResponse({"message": "Logout successful"}, status=200)
        _clear_auth_cookies(_resp)
        return _resp
    ...
```

## Redis JTI denylist

File: `backend/core/token_revocation.py`

```python
_NONCE_PREFIX = "jti_deny:"

def revoke_jti(jti: str, ttl_seconds: int) -> None:
    """Mark a JWT ID as revoked in Redis."""
    rc = _get_redis()
    rc.set(f"{_NONCE_PREFIX}{jti}", "1", ex=max(ttl_seconds, 1))

def is_jti_revoked(jti: str) -> bool:
    """Return True if the JTI is in the denylist."""
    rc = _get_redis()
    return rc.exists(f"{_NONCE_PREFIX}{jti}") > 0
```

Redis keys expire automatically once the token's natural TTL is reached —
no manual cleanup required.

---

## Middleware enforcement

`JWTAuthMiddleware` calls `is_jti_revoked(jti)` on every authenticated request.
A revoked JTI results in HTTP 401 regardless of the token's signature and expiry.

## simplejwt blacklist (rotation-based)

File: `backend/api/settings/base.py`

```python
INSTALLED_APPS = [
    ...
    "rest_framework_simplejwt.token_blacklist",
    ...
]

SIMPLE_JWT = {
    "ROTATE_REFRESH_TOKENS": True,
    "BLACKLIST_AFTER_ROTATION": True,
    ...
}
```

When a refresh token is rotated, the old token is blacklisted in the
`OutstandingToken` / `BlacklistedToken` SQL tables as a secondary safeguard.
