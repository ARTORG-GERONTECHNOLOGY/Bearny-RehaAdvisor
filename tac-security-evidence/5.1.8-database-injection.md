# Evidence — 5.1.8: Protection against database injection

## Summary

All database access uses the **MongoEngine ORM** (MongoDB) and **Django ORM**
(SQLite for Django internals). No raw queries are constructed from user input.
REDCap identifiers are validated with a strict regex before use.

---

## MongoEngine ORM — no raw queries

All MongoDB queries use the MongoEngine queryset API:

```python
# Pattern used throughout patient_views.py, auth_views.py, etc.
patient = Patient.objects.get(pk=ObjectId(patient_id))
user = User.objects.filter(email=email).first()
SMSVerification.objects(userId=user_id, code=code).first()
```

MongoEngine parameterises all queries — user input is never interpolated
into a raw query string or MongoDB shell command.

---

## ObjectId validation prevents injection

All document lookups by ID use `ObjectId(value)`, which raises
`bson.errors.InvalidId` if the value is not a valid 24-character hex string:

```python
try:
    patient = Patient.objects.get(pk=ObjectId(patient_id))
except (Patient.DoesNotExist, Exception):
    return JsonResponse({"error": "Patient not found"}, status=404)
```

An attacker cannot inject MongoDB operators (`$where`, `$gt`, etc.) via an
ObjectId field.

---

## REDCap identifiers — regex allowlist

File: `backend/core/views/` (REDCap import code)

REDCap record IDs are matched against a strict alphanumeric regex before
being used in any query, preventing operator injection via that field.

---

## No raw() / eval / $where queries

```
$ grep -rn "\.raw(\|__raw__\|\$where\|db.eval" backend/core/ \
    | grep -v "test\|__pycache__"
(no output)
```
